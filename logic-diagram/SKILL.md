# 逻辑图（Logic Diagram）

一段文字 → 从 141 页模板里选最合适的一页 → 填进去 → 出图。

**不做**：不自己画图、不生成 SVG。所有图形来自模板，本 skill 只负责「选对页 + 填对位置」。

## 资产

- `assets/template.pptx` —— 141 页纯净模板（已去页眉水印、已剥离 23MB 嵌入字体，2.1 MB）
- `assets/fonts/` —— 随包字体 `Noto Sans SC`（Regular/Bold，SIL OFL 1.1）与 `OFL.txt` 许可原文；首次出图自动装入用户字体目录
- `assets/index.json` —— 逐页索引，141 条
- `assets/thumbs/pNNN.jpg` —— 逐页缩略图（520×292，快速看图用）
- `references/SCHEMA.md` —— 索引字段定义
- `scripts/match.py` —— 内容特征 → 候选页排序
- `scripts/layout.py` —— 侦察某页的槽位、形状清单与阅读顺序
- `scripts/build.py` —— 填内容 → 出 PPTX/PDF/PNG
- `scripts/fonts.py` —— 字体与 LibreOffice 定位（`ensure_fonts()` / `find_soffice()`）
- `scripts/setup_fonts.py` —— 字体安装 / 检查 / 卸载 CLI

## ⚠️ 先读这条：模板分两类

| 类别 | 页数 | 页码 | 怎么填 |
|---|---|---|---|
| **纯占位符页** | 18 | 2,4,5,7,8,9,13,15,16,20,21,23,28,29,31,36,38,39 | `--spec` 自动配对 |
| **带示例内容页** | 105 | 其余大部分 | `--map` 显式映射（主力） |
| 混合页 | 18 | 1,3,6,10,14,18,19,22,24,25,27,30,32,33,34,35,37,40 | 视情况，多用 `--map` |

**绝大多数页（105/141）带的是真实示例文案**（如 p043 的「成长体系/付费体系/会员体系」），不是「输入标题文字」。这类页必须用 `--map` 指定「哪个形状换成什么」。
强行套 `--spec` 会报错退出（当页文本组数 ≠ 2），不会静默出错。

## ⚠️ 三条铁律（违反即返工）

### 铁律 1：先读内容，再选模板 —— 按逻辑类型选，不按「塞得下」选

选页不是「找个能塞下内容的格子」，而是**让内容的逻辑关系与图的结构同构**：

- 判断内容的逻辑类型（第 1 步 ②：对比 / 顺序流程 / 总分发散 / 环形关系…）
- 用 `match.py --logic <类型>` 按类型检索，**先看同类型的页**
- 再看缩略图，确认图的结构确实表达这种关系

**绝不为了凑槽位而扭曲内容结构**。如果内容是对照关系，却选了并列页，就是返工。
类型对上了、槽位数对不上，那是**内容颗粒度**要调（见铁律 3），不是换一个类型不对的页。

### 铁律 2：一份内容只出一页 —— 分页 = 梳理没做完

交付物是**一页**逻辑图，不是一套多页 PPT。

当你觉得「一页装不下、需要做第二页」时——**那不是页数问题，是内容梳理没到位**。
正确反应是回到第 1 步重新归纳，而不是加页：

- **合并同类项**：四条并列的环节若同属「对内」，归为一条主干 + 四个短语
- **砍掉论证过程，只留结论**：「为什么…因为…所以…」只保留「所以」
- **把细节降为短语**：整句描述压成 3–5 字的名词词组
- **上位概括**：一堆平级细节用一个上位词统起来

判断标准：若梳理后**信息不丢失、逻辑仍成立**，就说明压得对。
压不进去，多半是舍不得砍论证过程。

### 铁律 3：选定模板后，用内容填满它的每一个槽位

模板选定了，就是**内容为模板让路**（让的是措辞与颗粒度，不是逻辑本身）：

- **每个槽位都要有内容**，绝不留下空白槽位，也不允许某个槽位凑字数
- 先把内容重新裁剪成与槽位**一一对应**的条目：条数必须刚好等于槽位数
- 标题浓缩到**模板标题胶囊能容下的长度**（先 `layout.py` 量尺寸，p33 那类窄胶囊只有 4–5 字）
- 正文压进正文框容量（实测约 8–9 全角字/行），超一字就折行
- 字数在槽位间**均衡分配**，避免一格爆满、一格空荡

顺序是：**定逻辑 → 选模板 → 按槽位重裁内容 → 出图 → 看图核对**。
反过来（先写内容再找地方塞）必返工。

## 字体：随包自带 Noto Sans SC，首次出图自动安装

模板用的是「阿里巴巴普惠体」和「思源宋体 CN Heavy」，**两者都不可自由
分发，绝大多数机器上也没装**。LibreOffice 碰到不存在的字体名会按
fontconfig **各自乱回退**，同一页里主标题、卡片标题、卡片正文、编号可能
变成几款互不相干的字体（实测出现过手札体、华文仿宋、魏碑体混排）。

本 skill **随包携带 `Noto Sans SC`**（思源黑体的 Google 发行版，
SIL OFL 1.1，明确允许随包再分发），放在 `assets/fonts/`：

- `NotoSansSC-Regular.otf`（正文）
- `NotoSansSC-Bold.otf`（标题）
- `OFL.txt`（许可原文）

出图前 `build.py` 自动做两件事：

1. **`ensure_fonts()`** —— 检查系统里有没有 `Noto Sans SC`，没有就把
   `assets/fonts/*.otf` 装进**用户级**字体目录（无需 sudo）并刷新缓存：
   macOS `~/Library/Fonts`、Linux `~/.local/share/fonts`、
   Windows `%LOCALAPPDATA%\Microsoft\Windows\Fonts`。
   也可手动跑 `python3 scripts/setup_fonts.py`（`--check` 只检查、
   `--uninstall` 卸载、`--where` 看路径与状态）。

2. **`normalise_fonts()`** —— 把全页每个 run 的 `a:latin` / `a:ea` /
   `a:cs` / `a:sym` **无条件钉到** `FONT_TARGET`（默认 `Noto Sans SC`），
   字号、字重、颜色、对齐一律保留；若某个 run 连 `a:latin` 都没有（模板里
   6 个编号 01–06 就只定义了 `a:sym`），会补一个 `a:latin`——否则拉丁
   字符会落到主题默认字体，再被 fontconfig 回退成 `Liberation Mono` 之类。
   这一步是**默认行为**，不需要额外参数。

> 想换字体：`export FONT_TARGET='思源宋体'`（该字体需系统已装）。
> 想恢复模板原设计：把 `main()` 里 `normalise_fonts(slide)` 那一行去掉。
> 不要试图“还原模板原字体”——写一个装不上的字体名，结果仍不可控
> （带字重的名字如 `Source Han Serif SC Medium` LibreOffice 认不出，
> 照样乱回退）。钉死到确定存在的字体才可靠。

**排查方法：渲染后在 PDF 里查实际字体，不要靠肉眼猜** -

```bash
python3 -c "
import fitz
page = fitz.open('输出/xxx.pdf')[0]
seen = {}
for bl in page.get_text('dict')['blocks']:
    for l in bl.get('lines', []):
        for s in l['spans']:
            seen.setdefault((s['font'], round(s['size']), s['flags']), s['text'][:18])
for k, v in sorted(seen.items()):
    print(f'{k[0]!r:34} {k[1]:3d}pt  {v!r}')
"
```

一页里出现三四款字体名，就是回退失控了。

## 工作流

### 第 1 步：把内容读成结构

先把内容归纳成「若干条并列的要点」，判断三件事：

**① 有几条？** —— 顶层条目数，不是子条目总数。

**② 什么逻辑关系？** 按下表判断，再查索引分布：

- 有先后有箭头 → `顺序流程`（24 页）
- 有年份或阶段 → `时间轴`（9）
- 平等并列 → `并列要点`（20）
- 两方对照 → `对比`（11）
- 逐层收窄 → `层级金字塔`（13）
- 一个核心向外发散 → `总分发散`（29，最多）
- 首尾相接转一圈 → `循环闭环`（4）
- 环绕中心 → `环形关系`（9）
- 因为…所以 → `因果链`（3）
- 逐级淘汰 → `漏斗筛选`（2）
- 两维度交叉 → `二维矩阵`（4）
- 逐级上升 → `递进阶梯`（7）
- 平铺罗列 → `清单列表`（2）

**③ 每条多少字？** 决定容量是否够。超了会挤爆或折行（实测正文框约可容 8–9 个全角字，标题胶囊约 10 字）。

### 第 2 步：选页

```bash
python3 scripts/match.py --items 9 --logic 顺序流程 --chars-per-item 40 --top 8
```

`score` 是加权分（类型命中 +50、槽位差每格 −6、容量满足 +20…）。
**分数 < 55 说明没有真正贴合的页**，应换逻辑类型或改内容切分，别硬凑。

浏览某类：
```bash
python3 scripts/match.py --list --logic 对比 --slots 4
```

**候选页务必看缩略图**（`assets/thumbs/pNNN.jpg`）。索引是读图写的判断；**57 页 `confidence < 0.7`**，嵌套计数口径有分歧。

### 第 3 步：侦察版式

```bash
python3 scripts/layout.py --page 43
```

输出：文本分组、槽位数、阅读顺序、**形状清单**（id / 形状名 / 位置 / 尺寸 / 当前文字）。

**形状名是角色线索**（同一页内可靠）：

- `Object57` → 卡片**标题**
- `Object60` → 卡片**正文 / 列表项**
- `Object58` → 小**标签**（箭头注、轴标签）

（p007 那类占位符页则是 `稿定-9` 标题胶囊 / `稿定-31` 正文框。）

**id 含 `/` 表示文字藏在组合内部**，如 `3/0`。这很常见——模板把「图标 + 说明」打包成了组合，不递归就会漏掉。

### 第 4 步：填内容

**模式 A：自动配对**（仅 18 页纯占位符页）

```json
// content.json
{"heading": "主标题", "items": [{"title": "条目标题", "body": "条目正文"}]}
```
```bash
python3 scripts/build.py --page 7 --spec content.json --outdir ./输出
```
`items` 数量必须 == 槽位数，否则报错退出。

**模式 B：显式映射**（任何页，**主力**）

```json
// map.json
{
  "heading": "主标题（可选）",
  "replacements": [
    {"shape": "5",   "text": "拉新体系"},
    {"shape": "6",   "text": "渠道投放与裂变"},
    {"shape": "7/0", "text": "公域引流与私域承接"}
  ]
}
```
```bash
python3 scripts/build.py --page 43 --map map.json --outdir ./输出
```
先跑 `layout.py` 拿形状清单，对着缩略图决定每个 id 换成什么。**只写要改的，没写的保持原样。**

### 第 5 步：看图自检（不能跳）

打开生成的 PNG，逐项核对：

1. **顺序** —— 蛇形页要顺着箭头读
2. **溢出/折行** —— 文字有没有超框，或末尾孤字掉到第二行
3. **残留** —— 有没有忘改的示例文字（尤其**组合内部**的）
4. **空白** —— 有没有槽位空着
5. **字体** —— 主标题与卡片是否同款

## 陷阱

**组合内部的文字**：`slide.shapes` 只遍历顶层，约半数页面把文字打包在组合里。`layout.py` 已递归处理（id 带 `/`）。**改之前一定要看清单里有没有 `/` 的 id**——否则会残留「飞猪省钱卡项目」这类示例文案。

**蛇形折返**：约两成页面是「行1 左→右、行2 右→左」的折返走线（如 p007）。填错顺序会让内容读反。`layout.py` 会自动识别并提示 `⚠ 蛇形：第 [2] 行是从右往左读的`。

**容量**：实测正文框约容 8–9 个全角字、标题胶囊约 10 字。**超一字就折行**（如「会员权益与积分机制」9 字会把「制」挤到第二行）。宁可精简措辞。

**槽位数 ≠ 内容条数**：不要靠增删凑数，先换页。槽位分布：3 槽 30 页、4 槽 46 页、5 槽 32 页、2 槽 8 页、6 槽 10 页、7 槽 6 页、8/9 槽各 4 页、10 槽仅 1 页（p007）。

**字体**：随包 `Noto Sans SC` 会在首次出图时自动装入用户字体目录（见上节），无需手工下载。若 PDF 里出现 `Noto Sans SC` 之外的字体名（`PingFangTC`、`ArialUnicodeMS`、`LiberationMono`……），说明有 run 逃过了重钉——最常见的元凶是模板里只写了 `a:sym`、没有 `a:latin` 的元素。

## 索引口径

- `slot_count`：数**顶层并列项**。中心节点算 1；装饰箭头、标签、底部汇总条不计。
- 57 页 `confidence < 0.7`：嵌套层级计数口径有分歧，**用前先看图**。
- `placeholders` 只摘前 8 条；完整槽位以 `layout.py` 实测为准。

## 依赖

**Python 包（自行安装）**

```bash
pip install python-pptx pymupdf pillow
```

- `python-pptx` —— 读写 PPTX、替换文字
- `PyMuPDF`（`import fitz`）—— PPTX→PDF→PNG 以及**查实际字体**
- `Pillow` —— 图片处理

**渲染器（自行安装）：LibreOffice**，它提供 `soffice`。
`build.py` 会**自动探测**：环境变量 `SOFFICE` > `PATH` 里的
`soffice`/`libreoffice` > 常见安装路径（macOS 的
`/Applications/LibreOffice.app/...`、Linux 的 `/usr/bin/soffice` 等）。

- macOS：`brew install --cask libreoffice`
- Ubuntu：`sudo apt install libreoffice`
- 其他：<https://www.libreoffice.org/download/>
- 装在非标准路径时：`export SOFFICE=/path/to/soffice`

**字体已随包**（`assets/fonts/`，SIL OFL 1.1），首次运行自动安装，无需下载。

- **`inspect.py` 是禁区**：早期版本用过这个文件名，会撞 Python 标准库 `inspect` 导致 argparse 崩溃。已改名 `layout.py`，不要改回去。
