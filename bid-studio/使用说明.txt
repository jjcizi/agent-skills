标书超级工坊（bid-studio）使用说明
═══════════════════════════════════════════════════════════════════

版本：2.5.3
位置：bid-studio/（本说明与技能同目录）

───────────────────────────────────────────────────────────────────
一、这个技能是做什么的
───────────────────────────────────────────────────────────────────

「标书超级工坊」是投标全生命周期的一站式超级技能，融合了 8 个投标子
技能（标书解析、技术方案撰写、投标文件撰写、润色去 AI、图表 Mermaid、
定稿清理、合规审查等），并选择性融入 kami 排版审美体系。

它可以完成从「招标文件解析」到「Word/PDF 成品交付」的完整闭环，也支持
从任意中间环节切入（例如只润色已有标书、只审查已有投标文件）。

核心承诺：
  · 先锁定、再覆盖，先核对、后写作，先扫描、后写盘，先终检、后交付。
  · 全程不编造资质、业绩、参数、报价、测试数据；缺失信息一律用占位符
    标记并集中列出待补清单，等你补充。

───────────────────────────────────────────────────────────────────
二、如何唤起这个技能
───────────────────────────────────────────────────────────────────

在对话中直接说明意图即可触发，常用说法（任一即可）：

  · 「帮我写一份投标文件」「根据这份招标文件写标书」
  · 「解析这份招标文件」「做条款级标书解析」
  · 「写一份技术方案」（无需招标文件，仅凭需求描述）
  · 「润色已有技术标」「给技术标去 AI 化」
  · 「把技术标里的图统一成 Mermaid」「校验图表」
  · 「技术标定稿清理」「准备交付」
  · 「审查这份投标文件」「做合规/否决项审查」
  · 「导出成 Word / PDF」「排版并导出」

触发关键词：投标、标书、招标文件、标书解析、商务响应、技术响应、
报价响应、分包、逐章、终检、漏项、字数控制、去AI化、润色、扩写、
mermaid、定稿清理、合规审查、否决项、评分覆盖、知识库、图片嵌入、
师资填充、转Word、转PDF、排版、审美。

───────────────────────────────────────────────────────────────────
三、完整工作流程（P0 → P11）
───────────────────────────────────────────────────────────────────

  P0  知识库模式选择与搭建   （可选）先问是否启用 + 选甲/乙知识库，再建库
  P1  招标文件识别与分包锁定 （投标场景必做）锁定最小投标单元
  P2  条款级解析 + 反向漏检  （投标场景必做）产出解析总表/漏项清单/写作任务单
  P3  响应范围选择           （必问）选商务 / 技术 / 报价
  P4  结构拟定与一次性确认   （必做）章级 + 节级结构，你确认后落地
  P5  附件清单确认           （必做）附件清单与提交状态
  P6  正文撰写               （必做）先按「万」字设字数 + 产出图表规划表（6.0.1 前置门禁）；写正文时按规划自动判断并插入图表（数据→kami 数据图、流程/结构→Mermaid，不编造数据）
  P7  技术标润色与去 AI 化   （可选）
  P8  图表校验与规范化       （可选）Mermaid + 数据图校验/转换
  P9  定稿清理               （可选）
  P10 终检与合规审查         （交付前必做硬门禁）含废标项检查报告.pdf
  P11 输出格式确认与交付     （交付前必问）Word / PDF + 排版审美 + 表格格式 + 字体嵌入

───────────────────────────────────────────────────────────────────
四、你需要配合的「确认点」（技能会在这些地方停下来问你）
───────────────────────────────────────────────────────────────────

  1. P0 知识库模式选择（知识库场景必问）：技能会先问「本次是否启用
     甲/乙知识库？」——你选定后，再勾选用哪些知识库（甲方 / 乙方 /
     图片库）并给出文件路径或导入方式，同时告知乙方公司名称；导入完
     成后回复「确认知识库已填充」。未提供甲方资料或要求联网搜索时，
     技能会先分析标书需求，联网搜索与甲方高度相关的权威资料，保存到
     项目目录「甲方知识库/」（标注来源），不编造。
  2. P1 选包：多包项目时，技能列出全部包，你回复包号或包名。
  3. P3 范围：「本次要写商务 / 技术 / 报价哪几部分？」可单选/多选/全选。
  4. P4 结构：确认章级目录与技术节级结构（保留/增删/重排）。
  5. P5 附件：确认附件清单与提交状态（提交 / 暂不提交）。
  6. P6 字数 + 图表规划：「本次标书总字数多少万字？」可按商务/技术/报价分层指定，
     或给一个总字数由技能按评分权重拆分；同时技能会产出「图表规划表」
     （逐节预判配图类型并记录理由），未产出不开始写正文。
  7. P11 格式：「要 Word、PDF，还是两者都要？」

  确认之后技能会自动连续完成，不再逐段打断；P10 终检是自动硬门禁，
  未通过不会宣称「可交付」。

───────────────────────────────────────────────────────────────────
五、入口路由：不同场景从哪里开始
───────────────────────────────────────────────────────────────────

  你的意图                          工作区现状        切入阶段
  ─────────────────────────────────────────────────────────────
  写标书/技术方案（有招标文件）      空/仅有招标文件   P1（或先 P0）
  写技术方案（仅简要需求）           空               P6（技术方案模式）
  润色已有技术标 / 去 AI 化          已有技术标 .md    P7
  校验 / 统一图表为 Mermaid          已有技术标 .md    P8
  定稿清理 / 准备交付                已有技术标 .md    P9
  审查已有投标文件                   有投标成稿+招标   P10（只读审查）
  导出 / 排版成 Word 或 PDF          已有投标 .md      P11

  进入工作区后，技能会先扫描目录判断现状，再结合你的请求定位起始阶段，
  不会在已有成稿时假装从零重写。

───────────────────────────────────────────────────────────────────
六、典型使用示例
───────────────────────────────────────────────────────────────────

  示例 1（完整投标，从零开始）：
    「根据这份招标文件写投标文件」→ 技能按 P1→P11 推进，途中会在选包、
    范围、结构、字数、输出格式 5 处问你，其余自动完成。

  示例 2（只写技术标）：
    「只写技术响应文件，技术标 3 万字」→ 技能跳过商务/报价，只搭技术
    目录，按 3 万字拆分到各节。

  示例 3（已有标书，只要审查）：
    「审查这份投标文件」→ 技能只读对照招标文件，产出《审查报告.md》
    和否决项专表、评分覆盖表，不改你的正文。

  示例 4（已有技术标，润色 + 导出）：
    「把技术标去 AI 化，然后导出成 Word 和 PDF」→ 技能先 P7 润色，
    再 P11 确认格式后导出，默认嵌入字体。

───────────────────────────────────────────────────────────────────
七、内置字体与排版（kami 审美）
───────────────────────────────────────────────────────────────────

  技能已内置 kami 排版所需字体，位于 assets/fonts/，导出无需联网：

    TsangerJinKai02-W04.ttf        仓耳今楷 02（中文衬线主字体，商业字体）
    TsangerJinKai02-W05.ttf        仓耳今楷 02（中文衬线主字体）
    SourceHanSerifSC-Regular.otf   思源宋体 SC 常规（回退，开源）
    SourceHanSerifSC-Medium.otf    思源宋体 SC 中黑（回退，开源）
    JetBrainsMono.woff2            JetBrains Mono（等宽，开源）

  排版基调：暖羊皮纸底 #f5f4ed、墨蓝 #1B365D 单一强调色、衬线标题
  层级（标题不加粗、靠字号留白分层）、正文 10.5pt。

  字体嵌入（默认执行）：导出 Word/PDF 时默认把字体嵌入文件，防止在
  其他电脑打开丢字体、被替换为默认字体。详见 SKILL.md P11.5。

  授权提示：仓耳今楷 02 为商业字体，商用前请确认仓耳字库授权；如不便
  使用商业字体，可回退到开源的思源宋体 SC（审美仍为衬线风格）。

  表格格式（默认执行）：导出的 Word/PDF 中所有表格默认在页面内水平居中，
  并带可见边框、表头墨蓝底 + 白字（或墨蓝下边框）、长表跨页自动重复表头；
  表头行与第一列上下左右居中、其余单元格上下居中（数字右对齐、文本左对
  齐），杜绝「无边框、无表头」的裸表。详见 SKILL.md 11.6。

  图表（前置门禁 + 自动判断）：动笔前技能会先产出「图表规划表」（逐节
  预判配图类型，写入写作任务单，见 6.0.1 前置门禁）；写正文时按规划自动
  判断是否配图并按下述规则
  选型——kami SVG 图表（14 种内联原语：架构/流程图/树状/分层/维恩/泳
  道/状态机 + 象限/时间线 + 柱状/折线/环形/K线/瀑布）配自动选型决策树；
  需要可编辑图源码或语法校验时用 Mermaid（流程图/时序图/甘特图/状态图
  等），P8 统一校验规范化。详见 SKILL.md 6.9。

  图片尺寸（默认执行）：导出的 PDF 中所有图表/图片默认设 max-width:
  100%，自动缩放到页面可用宽度内，不因原始像素过大而超出页面或显示不
  完整；Word 中超宽图片等比缩放。详见 SKILL.md 图表审美规范。

  审美与格式（为什么 PDF 更接近 kami 原味）：PDF 默认复用 kami 的
  HTML + CSS 排版管线（暖羊皮纸底、墨蓝单强调色、衬线层级、行高/字距
  /留白栅格）经 WeasyPrint/Chromium 渲染，与 kami 直接输出一致；Word
  因引擎限制只能按「Word 落地映射」逐项逼近，审美上限低于 PDF（可编辑
  优先）。详见 SKILL.md 11.3 与「融入边界」。

───────────────────────────────────────────────────────────────────
九、注意事项（红线）
───────────────────────────────────────────────────────────────────

  · 不编造任何资质、业绩、参数、预算、报价、测试数据；缺失用占位并列出
    待补清单。
  · 占位符（【待用户补充：xxx】【待补】[待用户补: xxx] 等）在导出的
    Word/PDF 中默认加蛋黄色底色（#FFF3CD）标记，肉眼可一眼识别待补内容；
    补全后去除底色。
  · 日期、签字、盖章、份数、密封、电子标格式以招标文件为准。
  · 润色/图表/定稿清理等后处理，默认「扫描 + 清单 + 确认」后才落盘；
    审查默认只读、不改稿。
  · 终检/审查未通过，不得宣称「已完成 / 可交付」。
  · 交付前自动生成《废标项检查报告.pdf》于标书同目录（法定否决 7 种 +
    12 大类废标项逐一对应检查）；未生成或结论含 ❌ 不得交付。
  · 招标格式范本优先于排版审美；审美只作用于范本未约束的自由排版区。
  · 本技能不替代法务、合规、签章密封等人工终审。
